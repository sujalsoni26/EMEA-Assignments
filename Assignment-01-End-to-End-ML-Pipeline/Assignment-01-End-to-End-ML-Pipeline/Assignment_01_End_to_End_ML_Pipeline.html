Assignment 1 — End-to-End Machine Learning Pipeline¶

Dataset: Adult (Census Income), UCI Machine Learning Repository Task: binary classification. Predict whether a person earns more than $50K per year from census attributes.

I picked this dataset because it needs real cleaning. It has missing values hidden as "?", stray whitespace, inconsistent target labels and duplicate rows, and it mixes numeric and categorical columns. That makes it a good fit for a pipeline that has to handle all of those things.

Requirement Where it is covered
Data cleaning and handling of missing or inconsistent values Sections 2–3
Categorical encoding and feature scaling Section 5
Training a suitable ML model Section 6 (model comparison and tuning)
Evaluation with relevant metrics, each one explained Section 7
Code, evaluation results and a short conclusion This notebook, results/, figures/, Section 9

Pipeline overview

raw files ─► clean (strip, "?"→NaN, fix labels, dedupe, drop leaky/redundant cols)
          ─► stratified train/test split
          ─► ColumnTransformer
                numeric      : median impute → StandardScaler
                skewed money : median impute → log1p → StandardScaler
                categorical  : "Unknown" impute → One-Hot (rare levels grouped)
          ─► classifier (chosen by 5-fold CV, then tuned)
          ─► evaluation on held-out test set ─► saved model + metrics

What the audit found

# Issue Evidence Fix
1 Leading whitespace in every text field (" State-gov") has_leading/trailing_space = True str.strip()
2 Missing values hidden as "?" about 2.8k in workclass and occupation, about 0.9k in native_country replace with NaN, then impute inside the pipeline
3 Inconsistent target labels "<=50K" and "<=50K." (the test file adds a trailing dot) give 4 labels instead of 2 normalise to 0/1
4 Duplicate records 29 rows identical in every column, including the sampling weight. That rises to 52 once the label formats in issue 3 are unified drop them so the same record cannot end up in both train and test
5 Redundant feature education (text) maps one-to-one onto education_num keep only the ordinal education_num
6 Non-predictive or leaky column fnlwgt is a census sampling weight. It says how many people a row represents, not anything about the person drop
7 Heavily skewed money columns capital_gain and capital_loss are mostly 0, with a long tail up to 99,999 log1p transform before scaling
8 Rare categories native_country has 41 levels, many with only a handful of rows group them as "infrequent" inside the encoder

Issues 1–6 are fixed in a deterministic clean() function. Issues 7–8, and the imputation for issue 2, are fitted transformations, so they go inside the scikit-learn pipeline and are learned from the training data only. That keeps information from the test set out of training.

def clean(df: pd.DataFrame) -> pd.DataFrame:
    """Deterministic cleaning: no statistics are learned here, so it is safe to run before the split."""
    out = df.copy()
    txt = out.select_dtypes(exclude="number").columns
    out[txt] = out[txt].apply(lambda s: s.str.strip())                     # 1. whitespace
    out = out.replace("?", np.nan)                                         # 2. hidden missing values
    out["income"] = (out["income"].str.rstrip(".")                         # 3. "<=50K." → "<=50K"
                     .map({"<=50K": 0, ">50K": 1}).astype(int))
    out = out.drop_duplicates().reset_index(drop=True)                     # 4. true duplicate records
    out = out.drop(columns=["fnlwgt", "education"])                        # 5 & 6. redundant / non-predictive
    return out

Order of operations matters. Duplicates are removed before fnlwgt is dropped. Once the weight is gone, more than 6,000 extra rows look identical, for example young, single, full-time HS-grad workers. Removing them would distort the data, so only true duplicate records (identical in every original column) are removed.

5. Preprocessing: encoding and scaling¶

Column group Columns Steps Why
Numeric age, hours_per_week, education_num median imputation → StandardScaler Puts features on a common scale (mean 0, sd 1) so no feature dominates gradient-based or distance-based models just because of its units. The median is robust to outliers.
Skewed numeric capital_gain, capital_loss median → log1p → StandardScaler Compresses the long tail. log1p keeps 0 as 0.
Nominal categorical workclass, marital_status, occupation, relationship, race, sex, native_country constant "Unknown" → One-Hot Encoding (min_frequency=50, handle_unknown="infrequent_if_exist") These categories have no natural order. Integer label encoding would invent one (e.g. Sales < Tech-support), so one-hot is the right choice. Levels with fewer than 50 rows are merged into one "infrequent" column, which reduces noise and dimensionality. Unseen levels at prediction time do not crash the model.
Ordinal education already available as the ordered integer education_num Education has a real order, so an ordinal code keeps more information than one-hot would.

Everything lives in a single ColumnTransformer, so the exact same transformations run at training, cross-validation, test and deployment time, and everything is fitted on training folds only.

In [12]:
NUMERIC = ["age", "hours_per_week", "education_num"]
SKEWED = ["capital_gain", "capital_loss"]
CATEGORICAL = ["workclass", "marital_status", "occupation", "relationship", "race", "sex", "native_country"]

preprocess = ColumnTransformer([
    ("num", Pipeline([("impute", SimpleImputer(strategy="median")),
                      ("scale", StandardScaler())]), NUMERIC),
    ("skewed", Pipeline([("impute", SimpleImputer(strategy="median")),
                         ("log", FunctionTransformer(np.log1p, feature_names_out="one-to-one")),
                         ("scale", StandardScaler())]), SKEWED),
    ("cat", Pipeline([("impute", SimpleImputer(strategy="constant", fill_value="Unknown")),
                      ("onehot", OneHotEncoder(handle_unknown="infrequent_if_exist", min_frequency=50,
                                               sparse_output=False))]), CATEGORICAL),
], verbose_feature_names_out=False)

6. Model training and selection¶

I compare a majority-class baseline with three standard classifiers. All of them use the same preprocessing pipeline and are scored with 5-fold stratified cross-validation on the training set only.

  • Logistic Regression: a linear, interpretable model. It is the one that benefits most from scaling.
  • Random Forest: an ensemble of decorrelated decision trees that captures non-linearities and interactions.
  • Histogram Gradient Boosting: trees built one after another, each correcting the errors of the previous ones. It is usually the strongest choice on tabular data.

ROC-AUC is the main selection criterion because it does not depend on a threshold and is not distorted by the 76/24 imbalance.

Choosing the decision threshold¶

A classifier outputs a probability, and the default rule is to predict ">50K" when it is ≥ 0.5. With imbalanced classes, 0.5 is rarely the best cut-off. I pick the threshold that maximises F1 using out-of-fold predictions on the training set, so the test set has no influence on the choice.

In [17]:
oof_proba = cross_val_predict(final_model, X_train, y_train, cv=cv, method="predict_proba", n_jobs=-1)[:, 1]
prec, rec, thr = precision_recall_curve(y_train, oof_proba)
f1s = 2 * prec[:-1] * rec[:-1] / (prec[:-1] + rec[:-1] + 1e-12)
best_thr = float(thr[np.argmax(f1s)])
print(f"F1-optimal threshold (out-of-fold): {best_thr:.3f} → OOF F1 {f1s.max():.4f} "
      f"vs {f1_score(y_train, oof_proba >= 0.5):.4f} at 0.5")

7. Evaluation on the held-out test set¶

What each metric means¶

In this problem, positive = earns >50K. TP, FP, TN and FN are the cells of the confusion matrix.

Metric Formula Meaning How to read it here
Accuracy (TP+TN) / all Share of all predictions that are correct Easy to understand, but inflated by the majority class. Always predicting "≤50K" already scores about 0.76.
Balanced accuracy (TPR + TNR) / 2 Average of the recall on each class Corrects accuracy for imbalance. 0.5 means guessing.
Precision TP / (TP+FP) Of the people we flag as >50K, how many really are High precision means few false alarms. Matters when acting on a positive is costly (e.g. targeted offers).
Recall (sensitivity) TP / (TP+FN) Of the people who really earn >50K, how many we find High recall means few missed positives.
F1 score 2·P·R / (P+R) Harmonic mean of precision and recall A single number that is only high when both are high. Good summary for the minority class.
ROC-AUC area under the TPR-vs-FPR curve Probability that a random positive gets a higher score than a random negative Independent of the threshold. 0.5 is random and 1.0 is a perfect ranking.
PR-AUC (average precision) area under the precision-recall curve Precision averaged over all recall levels More informative than ROC-AUC under imbalance. The random baseline equals the positive rate (about 0.24).
Confusion matrix counts of TN, FP, FN, TP Shows exactly which errors the model makes Shows the trade-off between missed high earners (FN) and false alarms (FP).

10. Conclusion¶

What was done

  1. Cleaning. I took 48,842 raw records down to 48,790. I stripped whitespace from every text field, turned 6,465 hidden "?" entries into real missing values, merged four inconsistent target labels into two classes, removed 52 true duplicate records, and dropped the redundant education column and the non-predictive fnlwgt sampling weight.
  2. Missing values. Missing values were handled by understanding them first. Rows with missing workclass/occupation earn >50K only 9% of the time, against 25% for everyone else, so they were imputed as an explicit "Unknown" category instead of being overwritten with the mode.
  3. Encoding and scaling. I used one-hot encoding for the 7 nominal columns (rare levels grouped, unseen levels tolerated), kept the ordinal education_num, applied log1p and then standardisation to the very skewed capital columns, and standardised the remaining numeric columns. This turns 12 raw columns into 74 model features, and all of it happens inside one leak-free scikit-learn Pipeline.
  4. Modelling. Under 5-fold CV, Histogram Gradient Boosting (ROC-AUC 0.927) beat Random Forest (0.918) and Logistic Regression (0.899). After tuning it reached a CV ROC-AUC of 0.928.

Test-set results (9,758 unseen people, decision threshold 0.37 chosen from out-of-fold predictions):

Interpretation

  • The model ranks people very well (ROC-AUC 0.93). Its PR-AUC of 0.84 is 3.5 times the random baseline of 0.24, so it is genuinely good at finding the minority >50K class, not just riding the majority class.
  • Accuracy alone undersells the trade-offs. At the default 0.5 threshold accuracy is higher (0.877), but the model finds only 68% of the high earners. Moving the threshold to 0.37 raises recall to 79% at a moderate cost in precision, and gives the best F1. The right threshold depends on the cost of a false alarm versus a miss, which is a business decision. The pipeline makes it a single parameter.
  • The most influential inputs are marital status (a proxy for household structure), capital gains, age and education. These are plausible drivers of income, which adds confidence that the model learned real patterns.

Limitations and next steps. The data comes from the 1994 US census, so absolute income levels are dated. The data also contains sensitive attributes (sex, race). Their measured importance is small, but a proper fairness audit (e.g. comparing error rates by group) would be needed before any real use. Probability calibration and SHAP explanations would be natural extensions.
